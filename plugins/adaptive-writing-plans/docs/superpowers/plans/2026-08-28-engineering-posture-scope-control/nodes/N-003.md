**Status:** done
**Depends on:** N-001

**Contract refs:** none
**Design refs:** engineering-posture-scope-control@2

## Inputs

- Approved posture and provenance primitives from N-001
- Existing map schema, node readiness, invalidation, migration, and completion rules
- Profile-specific required and excluded capability sets from GUIDE.md
- Approved, finalise-plan-reviewed leaf plan with independently verifiable commit boundaries; this map brief alone does not authorize implementation.

## Outputs

- Posture-aware map and node schema with exact PostureRef inheritance/override rules
- ScopeProvenance required for executable capability-producing nodes and behavior-budget entries
- Maturity ceiling validation that removes out-of-scope work from execution and preserves it as a deferred candidate
- Subtractive finalization checks that report unsupported behaviors before suggesting additions

## Acceptance

- A node cannot become ready when its posture ref is missing/stale or a required behavior lacks approved provenance
- Capabilities above the selected profile ceiling are rejected from the executable DAG and retained with reason/evidence as deferred candidates
- Spike and experiment fixtures keep mandatory safety floors but reject speculative compatibility, HA, recovery, deployment, and operability work
- Reusable_internal and production fixtures apply their distinct definitions of done without an ordinal maturity comparison
- Map migration and completion checks preserve existing artifacts, node topology, decisions, and provenance
- Before implementation, the node is decomposed into a finalise-plan-reviewed leaf plan with exact paths, validation commands, and independent commit boundaries.
- Provider-derived behavior enters required scope only through normalized evidence and explicit provenance; conversation-only or unverified-persistence output cannot authorize execution.
