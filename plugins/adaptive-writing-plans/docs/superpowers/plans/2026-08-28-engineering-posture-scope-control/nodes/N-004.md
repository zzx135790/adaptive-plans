# N-004: Make the Design Gate and provider handoffs posture-aware

**Status:** done
**Depends on:** N-001, N-003
**Requirements:** R-PERSIST, R-PROVENANCE, R-BUDGET, R-PROMOTION, R-COMPAT, R-APPROVAL-UX, R-COMPOSE
**Contract refs:** none
**Design refs:** engineering-posture-scope-control@2

## Inputs

- Approved posture/provenance primitives from N-001
- Existing re-entrant Design Gate, provider catalog, routing, normalization, and approval rules
- Observed missing provider coverage for data, migration, and security
- Approved, finalise-plan-reviewed leaf plan with independently verifiable commit boundaries; this map brief alone does not authorize implementation.

## Outputs

- PostureRef, allowed/excluded capabilities, and behavior budget in DesignProfile and provider handoffs
- Provider result classification that preserves over-ceiling recommendations as evidence/deferred candidates without mutating canonical state
- Approval/waiver rules that bind exact design and posture hashes and keep critical missing coverage visible
- Re-entry rules for posture changes, promotions, conflicts, and stale provider/design evidence
- Hash-bound ApprovalBrief generation for design approval and waiver gates, rendered inline by the orchestrator.
- Capability-driven CompositionContract and conditional routing for mature design, grilling, domain, decision, scenario, and review providers.

## Acceptance

- Design routing exposes profile, exclusions, provider roles, provenance, missing concerns, and confirmation policy
- Provider recommendations outside the behavior budget cannot become requirements, decisions, map nodes, or implementation tasks automatically
- Critical uncovered concerns block approval until evidence or an explicit scoped waiver is recorded
- Changing posture after approval creates a new design revision and stales exact dependent references
- Structured and unstructured handoff tests preserve raw evidence and unknown extension fields
- Before implementation, the node is decomposed into a finalise-plan-reviewed leaf plan with exact paths, validation commands, and independent commit boundaries.
- A design or waiver gate emits a bounded inline summary and one explicit confirmation prompt; a file-only handoff is rejected.
- Routing prefers a contract-matching installed provider, reports dependency/mutability/persistence state, and requires evidence before any rewrite.
